# 評価プロトコル（成立ゲート「重要欄」）

状態: **凍結（2026-11-12、開発者承認：閾値「提案どおり」、修正時間タイマー追加）**。凍結コミットのハッシュは末尾に記録する。凍結後に判定用データを生成し、
判定は1回だけ行う。判定後に条件・閾値を変えた場合は変更履歴を残し、その判定は不合格扱いとし、使ったデータを未使用扱いにしない
（requirements.md 6章）。

## 1. 対象
- 端末抽出（Firebase AI Logic `ONLY_ON_DEVICE`、private-app）。対象欄: `fullName`（氏名・ローマ字）、
  `residenceCardNumber`（在留カード番号）、`periodOfStayExpiry`（在留期間の満了日）。
- 固定する版: プロンプト `EXTRACTION_PROMPT_VERSION`、出力スキーマ `EXTRACTION_SCHEMA_VERSION`、firebase SDK、
  Chrome 版、モデル（`chrome://on-device-internals` の表示）、端末。判定記録に全て書く。

## 2. データセット
- 全て `scripts/generate-sample-cards.py` による合成カード（実在書類の模倣なし・透かし付き・架空値）。
- **探索用 `explore`**（既存5枚）: プロンプト・画像処理・閾値の検討に使用済み。判定には使わない。
- **成立ゲート用 `gate`**（凍結後に生成、12枚）: 探索用と別の架空値。同じ値・同じ元カードの派生を集合間で共有しない。
  - 条件: 標準4、文字小（0.8倍）2、傾き（±4°）2、暗い・低コントラスト2、**欄欠落2**（満了日が空欄のカード1、
    番号が空欄のカード1。正解は null）。
- **リリース判定用 `release`**（20枚）: ゲート判定後に別途生成。成立ゲートには使わない。
- 各セットの `manifest.json` にファイル・SHA-256・条件・正解を記録し、生成と同時にコミットする。

## 3. 指標（欄別）
- 分母 N: その欄に正解値を持つ全実行。タイムアウト・拒否・構造不正も除外せず「未読」に数える。
- **完全一致（原表記）**: 候補が印字どおりの文字列と一致。
- **完全一致（正規化後）**: 許可した正規化の後で一致。許可する正規化は欄ごとに固定:
  - fullName: 前後空白の除去、連続空白を1つに。**大文字小文字・文字の置換は不可。**
  - residenceCardNumber: 前後空白の除去のみ。
  - periodOfStayExpiry: `YYYY年M月D日` / `YYYY-MM-DD` を ISO 日付に変換して比較（ゼロ埋めの差は許容）。和暦は対象外。
- **合否に使う指標**: fullName と residenceCardNumber は「原表記」、periodOfStayExpiry は「正規化後」。
- **未読**: 候補なし（null・空・タイムアウト・失敗）。 **誤候補**: 候補ありだが正規化後も不一致。
- **正解が空の欄**: 別集計。不要な値を提示した割合を報告。
- 判定は本人修正前の採用候補で行う。精度にかかわらず全欄の本人確認は省略しない。

## 4. 時間
- **初回準備時間**: モデル未取得からの `initializeDeviceModel()` 完了まで。端末依存のため報告のみ（閾値なし）。
- **ページ初回の抽出時間**: ページ読込後の最初の抽出。各判定で3回（探索用画像で）測り報告。
- **準備済み抽出時間（合否対象）**: 同じページで、探索用画像1枚で暖機した後のゲート画像の抽出。p50・p95・タイムアウト件数。
- **タイムアウト**: 30秒。超過は未読に数える。
- **修正時間（報告）**: 候補表示から6欄すべてチェック済みまで。比較対象: 空の状態から手入力で6欄チェック済みまで（同じカード）。
  計測はアプリの診断表示 `Confirm time` / `Manual entry time` で行う（ミリ秒、本人データを含まない）。
- **確認後PDFの誤記入**: チェック済みの値と PDF 上の文字の不一致件数（PDF のテキスト抽出で比較）。

## 5. 閾値（凍結）
N は各欄10（欄欠落カードを除く）。

| 欄 | 指標 | 合格 |
|---|---|---|
| fullName | 原表記の完全一致 | ≥ 7/10 |
| residenceCardNumber | 原表記の完全一致 | ≥ 9/10 |
| periodOfStayExpiry | 正規化後の完全一致 | ≥ 9/10 |
| 全欄 | 未読 | ≤ 2/10 |
| 正解が空の欄 | 値の提示 | 報告のみ |
| 時間 | 準備済み抽出 p95 | ≤ 15 秒（目標 10 秒は報告） |
| PDF | 確認後の誤記入 | 0 件 |

不合格時（requirements.md 6章）: 対象欄や本人書類を縮小。重要欄の確認・修正が成立しなければ、自動抽出を実演の成功として扱わない。

## 6. 手順
1. 本プロトコルを凍結（開発者承認 → コミット）。
2. `gate` セットを生成・コミット（凍結コミットより後であること）。
3. 実機で一連の実行（同一ページ、暖機1回の後にゲート12枚、各1回）。ページ初回の抽出を別に3回。
4. 結果を `data/eval/results/gate-<日付>-<端末>.json` に記録（形式は explore の結果ファイルと同じ）。
5. `node scripts/eval/score.mjs data/eval/gate/manifest.json data/eval/results/<run>.json` で採点し、
   `docs/eval/gate-results.md` に記録。
