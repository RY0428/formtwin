# 評価プロトコル（リリース判定・重要欄）

状態: **凍結（2026-11-14、開発者承認：閾値「提案どおり」、カード構成「下書きどおり」）**。凍結コミットのハッシュは末尾に記録する。
凍結後に `release` セット（20枚）を生成し、判定は1回だけ行う。判定後に条件・閾値を変えた場合は変更履歴を残し、
その判定は不合格扱いとし、使ったデータを未使用扱いにしない（requirements.md 6章）。成立ゲートのプロトコル
（`docs/eval/protocol.md`）の定義を引き継ぎ、違いだけをここに書く。

## 1. 対象・固定する版
- 端末抽出（Firebase AI Logic `ONLY_ON_DEVICE`、private-app、公開URL）。対象欄: `fullName`、`residenceCardNumber`、
  `periodOfStayExpiry`（ゲートと同じ）。
- 固定: プロンプト `spike-a-1`（ゲート後の修正版：文字列 `"null"` の禁止、印字に無い発音記号の禁止、文字と数字の置換禁止）、
  スキーマ `0.0.0-provisional`、firebase 13.3.0、判定時のビルド（コミット）、Chrome 版、端末（開発者の Mac）、
  Chrome の Gemma 4 フラグ有効（`device:check` の専用プロファイル。呼出しごとの実モデルは Chrome が示さないため
  「Gemma 4 要求下」と記録し、世代は断定しない）。

## 2. データセット `release`（凍結後に生成、20枚）
- `scripts/generate-sample-cards.py` の合成カード（実在書類の模倣なし・透かし付き）。探索用・ゲート用と別の架空値。
  同じ値・同じ元カードの派生を集合間で共有しない。
- 条件の内訳: 標準 6、文字小（0.8倍）3、傾き（±4°）3、暗い・低コントラスト 3、傾き＋暗い 1、
  **欄欠落 4**（満了日が空欄 2、番号が空欄 2。正解は null）。
- 値の内訳（ゲートで見つかった誤りを再確認するため）: 氏名に、発音記号が付きやすい綴り（例: JOAO、JOSE、FRANCOIS を
  発音記号なしで印字）を 4枚以上含める。番号に、紛らわしい文字（Q/0、O/0、I/1、S/5、B/8）を含むものを 6枚以上含める。
- `manifest.json` にファイル・SHA-256・条件・正解を記録し、生成と同時にコミットする。

## 3. 指標
ゲートと同じ（欄別の完全一致〔原表記／正規化後〕、未読、誤候補、正解が空の欄の値提示）。許可する正規化もゲートと同じ。
N は「その欄に正解値を持つカード数」: fullName 20、residenceCardNumber 18、periodOfStayExpiry 18。

## 4. 時間
- 準備済み抽出（同じページ、探索用画像1枚で暖機した後の release 20枚）: p50・p95・タイムアウト件数。タイムアウト 30 秒
  （アプリの上限と同じ）。超過は未読に数える。
- ページ初回の抽出・初回準備時間: 報告のみ。
- 修正時間: 自動実行では測れないため本判定の対象外。操作検証（U1）で協力者の実測を報告する。

## 5. 閾値（凍結）

| 欄 | 指標 | 合格 | 参考: ゲートの閾値 / 実績 |
|---|---|---|---|
| fullName | 原表記の完全一致 | ≥ 16/20（80%） | ≥ 7/10 / 9/10 |
| residenceCardNumber | 原表記の完全一致 | ≥ 16/18（約89%） | ≥ 9/10 / 9/10 |
| periodOfStayExpiry | 正規化後の完全一致 | ≥ 17/18（約94%） | ≥ 9/10 / 10/10 |
| 全欄 | 未読 | 各欄 ≤ 2 | ≤ 2/10 / 0 |
| 正解が空の欄 | 値の提示（文字列 `"null"` を含む） | ≤ 1/4 | 報告のみ / 1/2 |
| 時間 | 準備済み抽出 p95 | ≤ 15 秒（目標 10 秒は報告） | 同じ / 5.94 秒 |
| PDF | 確認後の誤記入 | 0 件 | 同じ / 0 |

不合格時（requirements.md 6章）: 原因を記録し、対象欄の縮小や警告表示の強化を検討する。修正後の再評価は新しい未使用セットで行い、
`release` セットを再利用しない。精度にかかわらず全欄の本人確認は省略しない。

## 6. 手順
1. 本プロトコルを凍結（開発者承認 → コミット）。
2. `release` セットを生成・コミット（凍結コミットより後）。生成の確認は manifest と1枚の目視（欄欠落の描画）だけ。
3. 開発者の Mac で `npm run device:check -- --eval release`（自動）: 暖機1回 → release 20枚を各1回抽出し、候補の値・時間・
   失敗理由を `data/eval/results/release-<日付>-mac.json` に記録。各カードで候補を採用し全欄確認して PDF を作り、PDF の
   文字を正解と照合して誤記入を数える。
4. `node scripts/eval/score.mjs data/eval/release/manifest.json data/eval/results/<run>.json` で採点し、
   `docs/eval/release-results.md` に記録。
